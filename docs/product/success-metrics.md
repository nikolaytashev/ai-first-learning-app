# MVP Success Metrics

Quantitative targets are not yet human-approved. The Product Manager must open a
decision issue before using a threshold to accept, reject or prioritize product
work.

## Candidate metric set

| Outcome | Candidate measure | Decision still required |
| --- | --- | --- |
| Users start learning | Onboarding-to-first-lesson completion rate | Target and measurement window |
| Users complete material | Lesson and pathway completion rates | Target, cohort and minimum sample |
| Users return | Day-7 and Day-30 learning retention | Targets and eligible-user definition |
| Learning feels useful | Post-lesson usefulness rating | Scale, collection frequency and target |
| Progress is trustworthy | Rate of progress-loss or incorrect-sync reports | Error budget and reporting source |
| Reminders help | Reminder-to-session conversion rate | Attribution window and privacy boundary |
| The app is stable | Crash-free sessions and API availability | Targets and observability provider |

## Guardrails

- Initial metrics must not require advertising identifiers.
- Telemetry is not approved merely because a metric appears in this document.
- Data collection, retention and consent must be agreed in the privacy decision.
- Vanity measures such as raw download count must not be the sole MVP success
  criterion.
